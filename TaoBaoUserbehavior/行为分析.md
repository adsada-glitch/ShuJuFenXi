# 淘宝用户行为数据分析（分析师解读版）

> 在原有代码与结果下面补充数据发现、业务含义、限制和后续建议。统计值沿用源材料，新增百分比保留两位小数。


## 1. 项目说明

使用 Hive 对淘宝用户的浏览、收藏、加购物车和购买行为进行分析，观察活跃时段、购买行为最多的商品与类目，并根据最近购买时间与购买频次进行 RF 用户评分。

- 操作方式：Windows DBeaver 连接虚拟机上的 HiveServer2。
- 环境：Hive 3.1.3、Hadoop 3.1.3、MySQL 元数据库。
- 目标分析区间：2017-11-25 至 2017-12-03，包含起止日期。
- 原始文件：Linux 上的 `/mnt/taobao/UserBehavior.csv`，约 3.5 GB。
- 分析表：`taobao.user_behavior`。
- [数据导入脚本](load.sql)
- [数据清洗脚本](clear.sql)
- [PV、UV 与重复购买行为分析](fenxi.sql)
- [时段、商品排行与 RF 分析](Script.sql)


## 2. 数据字段与指标

| 字段 | 当前表类型 | 含义 |
|---|---|---|
| user_id | STRING | 用户 ID |
| item_id | STRING | 商品 ID |

## 3. 数据导入

以下为 load.sql 的原始内容：

```sql
CREATE DATABASE IF NOT EXISTS taobao;
CREATE TABLE IF NOT EXISTS taobao.user_behavior (
`user_id` string comment '用户ID',
`item_id` string comment '商品ID',
`category_id` string comment '商品类目ID',
`behavior_type` string  comment '行为类型，枚举类型，包括(pv, buy, cart, fav)',
`timestamp` int comment '行为时间戳',
`datetime` string comment '行为时间')
row format delimited
fields terminated by','
lines terminated by '\n';

--加载
LOAD DATA LOCAL INPATH '/mnt/taobao/UserBehavior.csv'
OVERWRITE INTO TABLE taobao.user_behavior;

SELECT *
FROM taobao.user_behavior
LIMIT 10;
```

`LOAD DATA LOCAL` 中的路径指向 HiveServer2 所在服务器的本地文件系统，不是 Windows 路径。`OVERWRITE` 会替换目标表的数据；本地 CSV 作为恢复来源应保留。重新加载后，已有的去重和时间清洗结果也会被替换。

## 4. 数据清洗与检查


### 4.1 去掉完全重复的记录

```sql
-- 1. 去掉完全重复的数据
INSERT OVERWRITE TABLE taobao.user_behavior
SELECT user_id, item_id, category_id, behavior_type,
       `timestamp`, `datetime`
FROM taobao.user_behavior
GROUP BY user_id, item_id, category_id, behavior_type,
         `timestamp`, `datetime`;
```

按六列一起分组，仅保留每组一条记录。若同一时间戳的 datetime 表示不一致，应先统一时间格式，再核对是否仍有重复。

### 4.2 转换时间戳

```sql
--数据清洗，时间戳格式化成 datetime
INSERT OVERWRITE TABLE taobao.user_behavior
select user_id, item_id, category_id, behavior_type,
       `timestamp`,from_unixtime(`timestamp`,'yyyy-MM-dd HH:mm:ss')
       from taobao.user_behavior;
```

时间格式必须为 yyyy-MM-dd HH:mm:ss。月份与日期之间不能有双横线。转换使用的时区应与分析业务时区一致。

### 4.3 查看日期分布

```sql
select date(datetime) as day from taobao.user_behavior group by date(datetime)order by day;
```

检查是否包含目标区间的各日期以及异常值。日期函数对错误字符串可能产生意外结果，建议同时与原始时间戳转换结果对照。

### 4.4 过滤异常日期

```sql
--数据清洗，去掉时间异常的数据
insert overwrite table taobao.user_behavior
select user_id, item_id, category_id, behavior_type, `timestamp`, datetime
from taobao.user_behavior
where cast(datetime as date) between '2017-11-25' and '2017-12-03';
```

保留 2017-11-25 至 2017-12-03，包含两端。仅在时间转换正确后执行；范围外记录及日期转换结果为 NULL 的记录不会保留。

### 4.5 检查行为类型

```sql
--查看 behavior_type 是否有异常值
select behavior_type from taobao.user_behavior group by behavior_type;
```

预期行为值为 pv、fav、cart、buy。本语句只检查，不删除异常行为。

### 4.6 按原始时间戳核对每日行数

```sql
SELECT
    from_unixtime(`timestamp`, 'yyyy-MM-dd') AS actual_day,
    COUNT(*) AS total_rows
FROM taobao.user_behavior
GROUP BY from_unixtime(`timestamp`, 'yyyy-MM-dd')
ORDER BY actual_day;
```

直接从 timestamp 计算日期，便于与 datetime 对照。

清洗完成后，后续整表分析使用的是当前表的数据。重新执行 load.sql 会恢复原始记录，需要重新检查清洗状态；星期分析另限定为 2017-11-27 至 2017-12-03。

## 5. 分析逻辑说明

### 5.1 一天中的活跃时段

使用 `hour(datetime)` 提取 0～23 点，再分别统计四类行为数。结果是分析区间内各小时的累计值，并非某一天或每日平均值。

待分析：哪个小时浏览最多、哪个小时购买最多、两者高峰是否一致。

### 5.2 一周中的活跃分布

使用 `pmod(datediff(datetime, '1920-01-01') - 3, 7)` 生成星期编号，0 代表星期日，1～6 代表星期一至星期六。查询覆盖 2017-11-27 至 2017-12-03，便于比较一周七天。

没有记录的星期不会自动显示为零行。若日期列格式异常，应先修正再解释统计结果。

### 5.3 商品与类目排行

分别按 item_id、category_id 分组，计算浏览、收藏、加购物车和购买行为数，再按 buy 降序取前十。


### 5.4 RF 用户评分

只分析至少发生过一次购买行为的用户。

| 指标 | 计算方式 | 评价方向 |
|---|---|---|
| R | 2017-12-04 减去最近购买日期的天数 | 越小，购买越近期 |
| F | 用户的购买行为记录数 | 越大，购买越频繁 |
| R_rank | 对 R 升序做 DENSE_RANK | 排名越小越靠前 |
| F_rank | 对 F 降序做 DENSE_RANK | 排名越小越靠前 |
| R_score、F_score | 分别按排名使用 NTILE(5) 分组，再赋 5～1 分 | 越高越好 |
| score | R_score + F_score | 两项等权，总分 2～10 |

CTE 命名为 cte，用于保存同一条查询中的中间结果，并不会创建永久表。

### 6.3 汇总每位用户的行为

```sql
--每个用户的购物情况，加工到 user_behavior_count
create table taobao.user_behavior_count as
select user_id,
       sum(case when behavior_type = 'pv' then 1 else 0 end) as pv,   --点击数
       sum(case when behavior_type = 'fav' then 1 else 0 end) as fav,  --收藏数
       sum(case when behavior_type = 'cart' then 1 else 0 end) as cart,  --加购物车数
       sum(case when behavior_type = 'buy' then 1 else 0 end) as buy  --购买数
from taobao.user_behavior
group by user_id;
```

该语句创建 user_behavior_count，每位用户一行，保存四类行为的累计次数。

CREATE TABLE AS SELECT 在表已存在时会报错；原始表重新清洗后，此汇总表不会自动刷新，需要另行更新，否则后续比例可能使用旧数据。

**数据分析与后续使用**

- **用途：**一人一行的汇总表可支持“仅浏览”“收藏或加购但未购买”“一次购买”“多次购买”等分层。

### 6.11 用户 RF 评分结果

```sql
with cte as(
select user_id,
       datediff('2017-12-04', max(datetime)) as R,
       dense_rank() over(order by datediff('2017-12-04', max(datetime))) as R_rank,
       count(1) as F,
       dense_rank() over(order by count(1) desc) as F_rank
from taobao.user_behavior
where behavior_type = 'buy'
group by user_id)

select user_id, R, R_rank, R_score, F, F_rank, F_score,  R_score + F_score AS score
from(
select *,
       case ntile(5) over(order by R_rank) when 1 then 5
                                           when 2 then 4
                                           when 3 then 3
                                           when 4 then 2
                                           when 5 then 1
       end as R_score,
       case ntile(5) over(order by F_rank) when 1 then 5
                                           when 2 then 4
                                           when 3 then 3
                                           when 4 then 2
                                           when 5 then 1
       end as F_score
from cte
) as a
order by score desc
limit 20;
```

查询结果：
