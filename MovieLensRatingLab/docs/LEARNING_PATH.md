# 四周学习路线

目标是回答一个具体问题：**在严格的时间验证下，个性化评分模型能否稳定胜过简单基线，它对冷门电影是否同样有效？**

初版提供可运行的基线和评估框架。你负责提出假设、解释证据、实现矩阵分解，并记录结论为何成立或不成立。建议每周投入 4–6 小时；进度以验收成果为准。

## 开始前：建立自己的实验记录

先阅读 README，安装项目，然后在项目根目录运行：

```bash
python -m rating_lab run
python -m unittest discover -s tests -v
```

每次实验记录：问题、预期、只改动的因素、训练区间、验证区间、参数、随机种子、指标、解释与限制。保存代码版本和数据校验值。初版结果仅是基准，不是你的最终研究结论。

**区分公开基准与独立确认。** 初版已经公开本数据尾段的测试指标，后续在同一尾段比较 MF 属于公开基准上的探索。用验证集探索、调参和排查问题；若需要独立确认，应提前固定方案并准备另一份未查看的数据。本文后续所说的“最终测试”均指这份新保留的确认数据。开发时间范围内的滚动验证可检验稳定性，但不能凭空创造独立数据。

## 第 1 周：理解数据与分析边界

从数据说明和下载逻辑开始，确认一行表示什么、评分取值、时间戳含义，以及本项目实际使用了哪些字段。

亲手完成：

- 写出 3 个能被数据回答的问题和 2 个不能回答的问题。例如可以研究已记录评分的预测误差，但不能把未评分解释为不喜欢。
- 检查缺失、重复的用户与电影组合、评分范围、时间范围，以及每位用户和每部电影的评分数分布。
- 画出按时间的评分量与均值，解释总均值为何会受到用户组成、电影组成和活跃度的共同影响。
- 读懂全局时间切分：目标比例为 70% / 15% / 15%，相同时间戳不能跨集，因此实际比例允许略有差别。核查训练、验证、测试的时间顺序，而非只核查行数。
- 统计验证集中的新用户和新电影；所有“热门／冷门”标签只能使用训练集的评分次数。

验收：提交一页数据审计记录、至少两张有解释的图，以及可复核的切分边界。解释为什么按用户随机拆分不等于模拟未来。

建议提交：`docs: audit rating data and define the temporal evaluation question`

## 第 2 周：把基线讲清楚

阅读 `BiasModel(mode="global")`、`mode="movie"`、`mode="user_movie"` 的训练和预测逻辑。先在纸上用几位用户、几部电影计算一个小例子，再与程序结果核对。

亲手完成：

- 写出三种模型的预测公式，说明总体均值、电影偏置、用户偏置与正则化各自解决什么问题。
- 在验证集比较 RMSE 与 MAE，并解释它们对大误差的不同敏感程度。
- 用验证集选择正则化强度；保留所有候选值的结果，而非只保留最佳值。
- 查看新用户、新电影同时出现时的回退行为，确认预测有定义且保持在评分范围内。
- 跟踪训练集、验证集表现的差距，区分拟合能力与泛化能力。

验收：完成一张基线对照表、一张正则化曲线，并用自己的话说明“增加用户偏置”的收益是否超过复杂度代价。暂不依据测试集选择参数。

建议提交：`analysis: compare rating baselines and tune regularization on validation`

## 第 3 周：让结论经得起追问

阅读配对误差比较与按用户聚类的 bootstrap。把“平均误差更低”拆成效应大小、区间估计和适用人群三个问题。

亲手完成：

- 固定两组模型预测，在每次 bootstrap 中抽取用户，并保留抽中用户的全部评分；同一用户被抽中多次时，保留其抽样次数。
- 计算配对模型差值的区间，明确差值方向，例如 `RMSE(候选) − RMSE(基线)` 为负才表示候选模型更好。
- 比较按评分加权与按用户等权的指标。重度用户在前者中影响更大；两者对应不同目标，不能在看到结果后临时挑选。
- 按训练电影评分次数切片，报告每片的评分数、用户数和误差；为训练中未出现的电影单列一组。
- 写一段失败分析，抽查误差最大的记录，但不要根据少数个案替代整体证据。

验收：提交配对比较、切片表和限制说明。区间描述的是固定模型、当前数据时期和抽样假设下的评价不确定性；它不覆盖重训练波动、未来时间漂移或所有电影的代表性。同一电影被多人评分也可能带来跨用户依赖。

建议提交：`analysis: quantify paired uncertainty and inspect popularity slices`

## 第 4 周：亲手实现一个进阶模型

在基线接口之上实现带正则化的矩阵分解：用户向量与电影向量的内积，加上总体均值和偏置。先用很小的合成例子验证更新方向，再在真实训练集运行。

亲手完成：

- 只在训练数据建立用户与电影映射；未知 ID 使用明确的基线回退。
- 固定随机种子；在验证集选择隐向量维度、学习率、正则化和训练轮数。记录计算时间与参数数量。
- 用有意义的测试检查未知 ID、评分范围、重复运行和时间切分约束。
- 预先选定主要比较对象、主要指标与切片；在公开 100K 尾段比较时标注探索性质。若准备了新的确认数据，再做一次最终测试。即使矩阵分解输了，也分析原因并保留结果。
- 让另一位读者按 README 从干净环境运行。记录依赖、命令、数据许可和复现步骤。

验收：提交自己实现的模型、验证记录、最终报告，以及一段回答：“这个复杂模型值得使用吗？证据支持哪些范围内的结论？”

建议提交：`feat: implement regularized matrix factorization and evaluate the frozen model`

## 项目完成时，你应该能解释

- 为什么必须先定问题和评价目标，再挑模型。
- 为什么时间泄漏、调参泄漏与数据选择偏差会让结果看起来更好。
- 为什么评分预测更准，不能直接推出推荐排序更好、用户更满意或业务指标提升。
- 为什么区间跨过零不等于证明两个模型相同，区间不跨零也不等于改进具有实际价值。
- 为什么历史 MovieLens 教学基准适合练方法，却不足以代表今天的电影观众或线上推荐场景。

你在 GitHub 展示的核心成果应是：可运行代码、清楚的分析问题、可靠的评估、诚实的失败分析，以及可追溯的实验记录。
